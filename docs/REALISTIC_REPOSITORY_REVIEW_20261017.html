DSH Long-Context Execution: Implementation-to-Claim Alignment

1. Scope and evidence discipline

This review reconciles implementation and recorded claims in the frozen CURRENT sources. Four categories are kept separate throughout: frozen implementation/configuration, recorded test observation, historical checkpoint, and recommendation. CURRENT denotes the frozen repository version; it is not fresh deployed behavior, and nothing here was executed against Production. Short sentinel strings confirm only that a reply was exact, never that a model is accurate, and eight tokens do not constitute an accuracy benchmark. No SLA, guarantee, or two-full-1M acceptance is asserted, because the frozen sources do not establish one.

2. Execution path, defaults and final-wire counting

The request path begins at DSH, passes an output-alias guard and a loopback-only proxy, and reaches the SGLang backend. The gateway output guard rejects endpoint/provider overrides, requires chat messages, and clamps the output aliases to 8,192 before they leave that hook S0367:L13-L21. The forwarder then counts the final envelope with the running backend tokenizer, failing closed if counting is unavailable S0196:L88-L94.

The counting call itself is a real HTTP invocation: count_request constructs a Request against the tokenizer URL with a JSON-encoded payload and parses the response S0308:L43-L48; it validates that the returned count is an integer, that the model limit equals the context constant, and that the token IDs are a list of the same length, refusing otherwise S0308:L62-L67. This matters because defaults can change the token sequence. normalize_conditioning materializes an omitted function strict as Boolean false S0272:L9-L12 and continue_final_message as Boolean false via setdefault S0272:L4-L5. The recorded alignment observation explains why: an earlier tool request counted 7,689 tokens while inference processed 7,561, so warming one sequence could not guarantee a reusable prefix for the other S0346:L130-L130. The corrected live comparison is described as a fresh alignment check, explicitly not another near-1M capacity test S0346:L134-L134.

The gateway output guard's own clamp is data['max_tokens'] = min([8192]+limits) after the alias list is normalized S0367:L20-L21, while the long-context guard defines CONTEXT = 1048576, OUTPUT = 8192 and RESERVE = 256, and derives available output as context minus reserve minus counted input, refusing when that value is below one S0308:L19-L21S0308:L185-L193. The aliases also appear in the runtime policy: the 1M branch names the model with a 1M label and caps output at 8,192 S0005:L15-L17.

3. Long-request admission versus ordinary concurrency

Admission is a process-shared file lock inside a single LiteLLM replica, not any notion of repository sharing. The module docstring records the design intent: run in one LiteLLM replica, hold the process-shared flock until the stream closes, including cancellation or failure, and let ordinary requests avoid waiting on that lock S0308:L3-L5. A recorded deployment-guide note states that one gateway replica owns admission and that scaling replicas requires distributed ownership, since an independent lock would not enforce a shared long-request limit S0289:L50-L50. These are statements about replica count and a lock file, not about Git repositories or source forks.

Whether a request is long is decided by comparing counted input plus chosen output against LONG_THRESHOLD = 131072 S0308:L22-L23. The guard compares that sum against the threshold and, for a long request, removes any client-supplied metadata lease key before generating the real one S0308:L198-L201. It then acquires a server-side lease; the key is created server-side and any client-supplied metadata key is first removed by that same block S0308:L194-L197. Acquisition loops on a non-blocking flock with a deadline of 300 seconds and raises a 429 with a 30-second retry hint when exhausted S0308:L144-L153. Release is wired to the success and failure hooks S0308:L211-L218 and to the streaming-iterator hook's finally path S0308:L220-L226.

A recorded live check used a deliberately held admission lock rather than a fabricated GPU workload; the real authenticated gateway returned HTTP 429 after 300.36 seconds while ordinary DSH replies continued S0346:L22-L26. The source labels this as validating admission behavior and explicitly notes it is not two actual near-1M GPU requests S0346:L102-L102. The backend's running-request ceiling of 16 S0280:L89-L90 is described in the qualified operating boundary as an admission ceiling rather than a promise about 16 maximum-length requests S0346:L50-L50.

4. Cold, cached and conditional latency and memory

The cache path has three distinct branches, and the constants alone do not describe them. With a bounded probe configured, the guard calls the warm helper for the whole ID list; on CacheProbeMiss it falls through to incremental preparation, while a successful probe whose prompt-token count does not match raises a hard error S0308:L115-L126. When the probe times out and the abort request was acknowledged, the helper raises the typed CacheProbeMiss S0308:L91-L95; an abort that is not acknowledged instead raises a stop-escalation error rather than retrying blindly S0308:L93-L94. Incremental preparation then extends the prefix in WARM_STEP = 2048 blocks, refuses when cached tokens fall more than 512 below the previous extension, and yields between steps S0308:L26-L27S0308:L127-L138. The warming request IDs are generated inside warm_prefix S0308:L71-L76 and are unrelated to the long-admission lease keys created in the pre-call hook.

On the streaming handoff, the forwarder sets a first-content deadline of 15 seconds for the guarded long case S0196:L152-L153 and emits a typed context_cache_handoff_failed error payload when that deadline lapses S0196:L175-L179. The regression file covers that deadline separately, asserting that only the request's own ID is aborted and that the lease is released S0279:L175-L183.

5. Compaction

Compaction policy is selected per runtime context. The 1M branch chooses a thresholdRatio of 0.875 and 65,536 headroomTokens, while the 128K branch keeps 0.75, and existing model policies for the same provider and aliases are filtered out before the new ones are pushed S0005:L28-L33. The formula recorded in the guide is floor(min(context × ratio, context − reserved output − headroom)), evaluated as 917,504 estimated tokens for the 1M case S0346:L195-L199. Compaction is a between-steps estimate, not an exact final-wire count, so a single oversized tool result or attachment can still reach the request guard first and be refused S0346:L201-L201. That limitation is a configuration/design statement; the guide does not certify that every historical session compacts successfully.

6. Rollback and a cautious recommended verification workflow

Rollback is implemented, not merely documented. In the restore branch, the saved profile's SHA-256 is verified against its stored digest, the profile is written back through a temporary file and os.replace, and the restored bytes are asserted equal to the original S0010:L46-L51. The candidate specification itself asserts that the copied pod volumes and the first container's volumeMounts equal the originals, so a routine rollout compares these lists before patching S0010:L70-L71. That comparison is a specification equality check on the candidate manifest; it does not prove that no future change could repoint storage, that every user file is preserved, or that all concurrent writes are protected.

The proxy promotion path additionally re-reads the gateway deployment after preparing its immutable ConfigMap and raises an error refusing to continue when the live spec no longer matches the plan, preserving concurrent edits S0304:L151-L153. The same builder appends the context-forwarder sidecar to the pod container list S0304:L100-L100, and the transport fixture asserts that the managed origin's header timeout is extended to one hour while the listed unrelated origins keep the caller's own options unchanged S0357:L5-L12. This fixture is a source-level test definition; it is not evidence that the test was executed here, and its assertions cover the managed origin plus the specific listed unrelated-origin cases rather than every possible origin.

Recommended operational workflow, offered as guidance rather than recorded fact: verify the frozen executable definitions first — the callback constants, normalization defaults, admission threshold and wait, warming step and probe, and handoff deadline — without touching a live runtime. Then reproduce the frozen regression suites in a disposable namespace, and if a live check is authorised, use only the named disposable probe pods, capture the backend tokenizer output, and save the raw evidence under a new filename rather than re-using an older pass S0346:L104-L106. Keep a compatible old image and the in-PVC profile backup, and confirm the saved hash matches before starting the old image on rollback S0010:L46-L51. Read back the running image, mounted configuration and a real client turn afterwards, because configuration, source tests, deployment and user-facing behavior remain distinct categories S0289:L54-L56. Do not describe the route as delivered end-to-end 1M until those gates pass, and do not treat one long request as evidence that two maximum-length requests fit.
