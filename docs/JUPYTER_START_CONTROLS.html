Jupyter Start and administrator controls

Start is safe to repeat. An already-enabled Jupyter service keeps its process, restart counter, settings and kernel variables. The dashboard reports: “Service is already enabled. Its process and settings were left unchanged.”

An enabled service that is recovering remains under its existing supervisor. Start does not force a restart or reset recovery; check the displayed status.

Choose the intended action

ActionEffectRunning kernels
Start, already enabledNo service-file write or restart-counter changeContinue unchanged
Start, stoppedEnables the existing service; the supervisor starts itA new server becomes available
RestartExplicitly replaces the supervised processInterrupted; save work first
StopDisables automatic startup and stops the managed processInterrupted; save work first

Administrator steps

  1. Open Admin overview → Managed startup services.
  2. Locate Jupyter for the intended runtime, owner and environment. Main DSH has private owner/environment pairs. DSH2 and DSH3 keep their designated owner and assigned Internet environment.
  3. Click start. Repeated Start does not ask for a destructive-action confirmation. An already-enabled service returns the unchanged message.
  4. If stopped, wait for running, then open JupyterLab. Opening Jupyter also reuses an existing server.
  5. Use restart or stop only when interruption is intended. They retain confirmation prompts. Saving a changed running service definition may replace its process; do not use Save as a substitute for Start.

Storage and kernel memory

Notebooks, settings and DSH histories remain in their existing private storage. Start does not move or copy them. Saved files persist; kernel variables are in-memory state and do not survive a full workspace restart.
