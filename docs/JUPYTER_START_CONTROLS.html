Jupyter Start and administrator controls

Start without interrupting an open notebook

Start is safe to repeat. When a managed Jupyter service is already enabled, Start leaves its process, restart counter and saved service settings unchanged. The dashboard reports: "Service is already enabled. Its process and settings were left unchanged." Existing notebooks and kernel variables remain available.

An enabled service that is recovering remains under its existing supervisor; Start does not force a restart or reset recovery. Check the displayed status.

ActionEffectRunning kernels
Start, already enabledNo service-file write or restart-counter changeContinue unchanged
Start, stoppedEnables the existing service; the supervisor starts itA new server becomes available
RestartExplicitly replaces the supervised processInterrupted; save work first
StopDisables automatic startup and stops the managed processInterrupted; save work first

Administrator steps

  1. Open Admin overview, then Managed startup services.
  2. Locate the Jupyter row for the intended runtime, owner and environment.
  3. Main DSH has private owner/environment pairs. DSH2 and DSH3 use their
  4. designated owner and assigned Internet environment.
  5. Click start. Repeating Start does not ask for a destructive-action
  6. confirmation. An already-enabled service returns the unchanged message.
  7. If the service was stopped, wait for its status to become running, then
  8. open JupyterLab. Opening Jupyter also reuses an existing server.
  9. Use restart or stop only when interruption is intended. These actions
  10. retain their confirmation prompts. Saving a changed running service definition
  11. may also replace its process; do not use Save as a substitute for Start.

Notebooks, settings and DSH histories remain in their existing private storage. Start does not move or copy them. Saving files provides persistence; kernel variables are in-memory state and do not survive a full workspace restart.

Stop, Restart and automatic startup for Jupyter and managed apps

Existing on-demand server

If the dashboard reports Waiting for existing Jupyter, a server started before managed autostart may still be running. Leave it in place while notebooks are active. The supervisor waits for its natural exit and then launches the enabled managed service. Stop disables future startup but does not stop this unowned server during the handover.

Autostart defaults and Internet approval · Operator backfill procedure

Internet approval pending means the account is enabled but its Internet environment is not approved. It is different from Account disabled. Failed startup retries remain Recovery retry pending, rather than being described as an existing server.
