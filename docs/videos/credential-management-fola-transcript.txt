Open the Credentials page from your private DSH workspace. Confirm your current account password, then choose an approved connection profile. Enter an alias, workspace name, permitted actions and expiry. Enter the provider token only in the dedicated secret field, never in chat. The browser encrypts that value for the selected credential broker before submitting it. The broker checks your account, environment and scope, then stores the value in OpenBao. The harness receives an alias and permitted results, not the stored token. No Internet connections use the internal broker. Internet connections use a separate broker with different network rules. Switching environments does not transfer connections. A workspace name is a policy label inside your private runtime, not a separate execution boundary between your own projects.

Use the connection adapter to list your aliases and request an approved operation. Read operations stay within the selected resources. A write request waits for your confirmation in the Credentials page. Review its parameters before approving it once. Changed requests and replayed approvals are denied. If a write has an uncertain outcome, check the provider before requesting another write. Central activity records exclude secret values. You can replace, disable or delete your stored connection. Deleting it stops broker access, but provider revocation remains a separate action. Existing login passwords and Kerberos authentication are unchanged. This release supports configured API token and personal access token connectors; it does not provide OAuth consent or Kerberos ticket acquisition. Operators retain encrypted backups and use a separate protected recovery process when the vault restarts sealed.
