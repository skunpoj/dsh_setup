Application sharing

A silent, captioned instructional illustration of application audiences, checkbox selection, editing and private Jupyter boundaries.

  1. Share an ordinary application. Open My applications in the intended environment. Select New application, enter a unique name and the port of your running app. A saved URL does not start the app.
  2. Choose who can open it. New ordinary apps default to all authenticated users. Choose owner only, all local users, all AD/LDAP users, or selected local users before saving when a narrower audience is needed.
  3. Select local users. Choose Selected local users. Tick the intended enabled local accounts. AD/LDAP accounts are not listed in this picker; use the AD/LDAP audience option for that group.
  4. Edit without widening access. Use Edit on an existing application. Review its saved audience and selected accounts. Opening the form does not save changes or broaden access. Old saved mixed lists are preserved until explicitly replaced.
  5. Verify from another account. After saving, an allowed visitor signs in at the application URL. Check that an unlisted account is denied when using a selected audience. Sharing is limited to the named application route.
  6. Keep Jupyter private. Jupyter, web terminals and management ports remain owner only. Sharing an ordinary application does not grant access to the notebook server, terminal or workspace of another user.
  7. Remove access safely. Edit the audience or remove the shared URL when access is no longer needed. Authorization is rechecked for shared HTTP and WebSocket routes. Saved application files and histories stay in place.
  8. Keep data under control. Review what the application displays. A shared app can expose data returned by its own code. Select recipients deliberately and keep protected data out of Internet staging.
