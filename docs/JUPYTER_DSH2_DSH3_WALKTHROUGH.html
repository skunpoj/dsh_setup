Jupyter and application lifecycle

A silent, captioned instructional illustration of Start, Stop, Restart and automatic startup for Jupyter and managed applications.

  1. Choose owner and environment. In Admin overview, open Managed startup services. Select the intended owner, runtime and environment before changing any service.
  2. Register an application. Save its private application URL and port. An administrator then saves its workspace command as a managed service. A URL alone does not start a process.
  3. Repeat Start safely. Start enables a stopped service. When already enabled, it leaves the saved definition and running process unchanged. Recovery stays with the supervisor.
  4. Stop means stay stopped. Stop disables the managed service and ends its process. It remains stopped after workspace replacement. Opening Jupyter cannot override Admin Stop.
  5. Restart is intentional. Restart replaces the managed process. Jupyter kernels and unsaved memory are interrupted. Save notebooks and application data before restarting.
  6. Autostart enabled services. Enabled Jupyter and registered apps start automatically after workspace replacement, when access is allowed. Stopped services remain disabled.
  7. Keep durable data private. Saved notebooks, preferences, application files and DSH history stay in private durable storage. Kernel variables and unsaved process memory do not persist.
