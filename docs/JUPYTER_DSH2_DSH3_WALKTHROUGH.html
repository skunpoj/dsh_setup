Jupyter Start in DSH, DSH2 and DSH3

A silent, captioned instructional illustration of safe repeated Start, startup when stopped, kernel preservation and explicit Restart or Stop.

  1. Choose the correct runtime. In Admin overview, open Managed startup services. Main DSH uses the selected owner and environment; DSH2 and DSH3 keep their assigned owners.
  2. Use Start without restarting. Start enables a stopped service. If Jupyter is already enabled, Start does not change its process, restart counter or saved service settings.
  3. Keep notebook kernels running. Repeated Start leaves the existing Jupyter server and kernel variables in place. Continue using your open notebook or Python console.
  4. Start a stopped service. When Jupyter is stopped, Start enables its managed service. The supervisor launches it in the owner workspace; then open JupyterLab.
  5. Use Restart deliberately. Restart explicitly replaces the service and interrupts its kernels. Stop prevents automatic restart. Save notebooks before either action.
  6. Save notebooks and settings. Saved notebooks, settings and DSH histories stay in their existing private storage. A full workspace restart still ends in-memory kernel state.
