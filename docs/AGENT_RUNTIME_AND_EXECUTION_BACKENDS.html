Agent runtime and execution backend

This reference separates the deployed control plane from runtime capabilities that still require bounded live acceptance.

Available now

Authenticated Web DSH, Web Terminal and installed managed-client entry points operate in the user's assigned private workspace. The deployed /agent-tasks broker advertises sdk, claude and deepagents, and rejects unauthenticated broker requests. Web Terminal includes a pinned, checksum-verified kubectl v1.32.9 client. It has no automatic service-account token or default kubeconfig, so the binary alone grants no cluster access. OpenShell remains disabled and is not user-selectable.

Deployed runtime choices and acceptance status

DSH Python SDK

The broker exposes the checkpointed Python agent runtime. Tool interrupts pause as awaiting_approval and resume only after explicit approval.

Claude Code

The broker exposes the managed coding-agent launcher for the selected private project.

Deep Agents

The broker exposes the installed managed Deep Agents runtime through the same project and admission boundary.

Broker health, authentication and capability mapping are verified live. Guarded live model execution for each runtime is not yet accepted and must not be inferred from the capability list.

Web DSH compared with the Python SDK

Web DSH is the authenticated control surface: it chooses the runtime, project, write mode and execution backend, then displays state and output. The Python SDK is one runtime behind that surface: it creates the programmatic agent, invokes tools, saves its checkpoint and resumes an approved interrupt. Choosing it does not turn ordinary DSH chat into an SDK conversation and does not give the browser a model credential.

Deployed behavior and remaining acceptance boundary

The authenticated gateway and broker are deployed with direct SDK runner source, private checkpoints, explicit task and paused-action approval, workspace confinement, one-active-task admission, persisted event polling, cancellation and restart interruption recovery. The immutable runtime image, running digest, broker health and authentication boundary are verified. Guarded live model execution for each runtime, model-ledger reconciliation and OpenShell acceptance remain unverified.
