Agent runtime and execution backend

This reference separates the current product from the approved target design. It is not evidence that the planned web task form is deployed.

Available now

Authenticated Web DSH, Web Terminal and installed managed-client entry points operate in the user's assigned private workspace. DSH chat, DSH CLI/SDK entry points and Claude Code are distinct clients. Azure source contains a guarded OpenShell gateway hook, but it is disabled and is not user-selectable.

Target runtime choice — not deployed

DSH Python SDK

Planned for programmatic DSH workflows, tools and event streams controlled by the authenticated task broker.

Claude Code

Planned as the managed coding-agent process launched in the selected private project through the same guard.

Target execution backend — not deployed

Private DSH workspace

The planned default backend retains the user's normal workspace boundary.

OpenShell isolated workspace

Optional and fail-closed. It remains unavailable until all 25 Test gates, rollback, namespace, node, budget and expiry are qualified.

Acceptance boundary

The candidate runtime contains the official SDK and guarded Claude launcher. The SDK has one successful guarded Test turn. That does not establish the web broker, guarded Claude acceptance, Production promotion or OpenShell acceptance. The selectors become user documentation only after source tests, immutable-image build, private Test deployment, bounded live acceptance, running-digest readback and affected-behavior verification pass.
