Scope and evidence discipline\n\nThis review reconciles implementation and recorded claims in the frozen CURRENT sources. Four categories are kept separate throughout: frozen implementation/configuration, recorded test observation, historical checkpoint, and recommendation. CURRENT denotes the frozen repository version; it is not fresh deployed behavior, and nothing here was executed against Production. Short sentinel strings confirm only that a reply was exact, never that a model is accurate, and eight tokens do not constitute an accuracy benchmark. Execution path, defaults and final-wire counting\n\nThe request path begins at DSH, passes an output-alias guard and a loopback-only proxy, and reaches the SGLang backend. The gateway output guard rejects endpoint/provider overrides, requires chat messages, and clamps the output aliases to 8,192 before they leave that hook [S0367:L13-L21]. The forwarder then counts the final envelope with the running backend tokenizer, failing closed if counting is unavailable [S0196:L88-L94].\n\nThe counting call itself is a real HTTP invocation: `count_request` constructs a Request against the tokenizer URL with a JSON-encoded payload and parses the response [S0308:L43-L48]; it validates that the returned count is an integer, that the model limit equals the context constant, and that the token IDs are a list of the same length, refusing otherwise [S0308:L62-L67]. Long-request admission versus ordinary concurrency\n\nAdmission is a process-shared file lock inside a single LiteLLM replica, not any notion of repository sharing. The module docstring records the design intent: run in one LiteLLM replica, hold the process-shared flock until the stream closes, including cancellation or failure, and let ordinary requests avoid waiting on that lock [S0308:L3-L5]. A recorded deployment-guide note states that one gateway replica owns admission and that scaling replicas requires distributed ownership, since an independent lock would not enforce a shared long-request limit [S0289:L50-L50]. These are statements about replica count and a lock file, not about Git repositories or source forks.\n\nWhether a request is long is decided by comparing counted input plus chosen output against `LONG_THRESHOLD = 131072` [S0308:L22-L23]. The guard compares that sum against the threshold and, for a long request, removes any client-supplied metadata lease key before generating the real one [S0308:L198-L201]. It then acquires a server-side lease; the key is created server-side and any client-supplied metadata key is first removed by that same block [S0308:L194-L197]. Acquisition loops on a non-blocking flock with a deadline of 300 seconds and raises a 429 with a 30-second retry hint when exhausted [S0308:L144-L153]. Release is wired to the success and failure hooks [S0308:L211-L218] and to the streaming-iterator hook's `finally` path [S0308:L220-L226].\n\nA recorded live check used a deliberately held admission lock rather than a fabricated GPU workload; the real authenticated gateway returned HTTP 429 after 300.36 seconds while ordinary DSH replies continued [S0346:L22-L26]. The backend's running-request ceiling of 16 [S0280:L89-L90] is described in the qualified operating boundary as an admission ceiling rather than a promise about 16 maximum-length requests [S0346:L50-L50].\n\n## 4. With a bounded probe configured, the guard calls the warm helper for the whole ID list; on `CacheProbeMiss` it falls through to incremental preparation, while a successful probe whose prompt-token count does not match raises a hard error [S0308:L115-L126]. Compaction\n\nCompaction policy is selected per runtime context. The 1M branch chooses a `thresholdRatio` of 0.875 and 65,536 `headroomTokens`, while the 128K branch keeps 0.75, and existing model policies for the same provider and aliases are filtered out before the new ones are pushed [S0005:L28-L33]. Compaction is a between-steps estimate, not an exact final-wire count, so a single oversized tool result or attachment can still reach the request guard first and be refused [S0346:L201-L201]. That limitation is a configuration/design statement; the guide does not certify that every historical session compacts successfully.\n\n## 6.
